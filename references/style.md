# 风格规则：石墨线稿

一句话：**深石墨底上一笔亮色圆头细线画出物件，物件里垫一层半透明白的平涂实形，强调色是一块填色，只点一处。** 线和界面图标（Lucide 1.5 px）是同一种圆头细线，图标放大到 1024 后线宽 60；1024 全出血母版、分层（iOS 26 的 Icon Composer：背景 + 3 组）、六种外观和交给系统的 Liquid Glass 学 Apple 的 HIG；单色主题图标、自适应图标和 Play 规格学 Google。

这份文件是所有数字的唯一出处。所有 px 都是缩放后的最终像素（1024 画布上），不是源坐标；源坐标 = 最终像素 ÷ k（k 是 `#subject` 的 scale）。角、安全区要手查，其余数字 `scripts/render.py` 每次都逐条打印，标 PASS / FAIL / INFO，以它为准。

## 原则

1. **线，加一层体积。** 主体是 1–4 段相连的线，全部同一个线宽 60、圆头圆角，线本身不填色。线稿和界面里的 Lucide 图标一个画法，图标和界面读起来是一个品牌。线围出来的物件内部垫一层半透明白（`#FFFFFF`，不透明度 .14）的平涂实形 `#volume`，边沿藏在线下面：Apple 要图标用重叠的实形和不同透明度的层，Liquid Glass 在这一层上做出厚度，线稿也就不再是一根发丝。
2. **净空就是结构。** 分开的两段线之间、线和强调色之间都至少隔一个线宽（60）。比线宽窄的缝在小尺寸会糊住。
3. **一眼看懂。** 一个隐喻，画一个具体的物件（秒表、云、饼图），几笔就能认出来，主屏上扫一眼就知道是什么 app。
4. **强调色只点一处。** 一块填色（扇形、圆、弓形、胶囊、斜带），最好就是物件里最有意义的那一块（计时的进度、天气的太阳、记账抽出的那一块）。不用强调色描线：60 宽的彩色线在 29 px 和单色 50 % 灰下会消失，一块填色还在。这是旧线稿风格「一笔线 + 一块色」的做法。
5. **几何。** 线只用直线、圆弧、圆角多边形（含播放三角）；强调色只用圆、扇形、弓形、环段、胶囊、圆角多边形。每一笔都能报出尺寸。
6. **顶光，不画立体。** 底是石墨竖直渐变（Apple 要的「简单的背景渐变」），线是一束顶光照下来的亮灰渐变。不画辉光、投影、高光、折射，也不用任何滤镜：iOS 26 的 Liquid Glass 按层自己加，烤进去的光在 Clear、Tinted 外观里会变脏。
7. **类别看图形。** 工具、图片、视频、AI 四类各有一个固定的形状记号，见「类别记号」。只靠颜色，用户说不出类别。

## 线宽为什么是 60

- Lucide 在 24 格上画 2 单位的线；图标主体的活动区约 640 px，一格约 30 px，2 单位就是 60。界面里 20 px 图标的 1.5 px 线按同样比例约 56，两者看起来是一种线。
- 60 在 40 px 时约 2.3 px，29 px 时约 1.7 px。64 px 及以下用 small 版，线加粗到 76（29 px 约 2.2 px），体积层保留。
- 线宽只有一个。不画粗细对比，不画发丝线。

## 构成

```
#background      石墨底：1024 全出血 rect，fill url(#bg)
#subject         整体缩放和居中（transform），data-shape，data-category（属于四类或健康、财务时）
  #volume        一个平涂实形：fill #FFFFFF，fill-opacity .14，第一个子元素，边沿走线的中线（藏在线下）；没有内部的线稿不画，#subject 写 data-volume="none"
  #body          <g fill="none" stroke="url(#body-fill)" stroke-width="60 ÷ k" stroke-linecap="round" stroke-linejoin="round">：所有线的中线
  #accent-shape  一个元素：强调色填色，fill url(#accent)，不描边
```

三个子元素就是 Icon Composer 的三组：1 体积层、2 线稿、3 强调色（Apple 上限 4 组），图层都是 1024 方形、不带遮罩。

只画默认（石墨）外观。浅色、深色、单色、小尺寸版和 Apple 的六种外观由 `render.py --variants` 生成，配方在 `construction.md`「外观」。商店 A/B 测试用的浅一档底、细亮边、类别色底由 `render.py --store-ab` 生成，是额外导出，不是第二种风格。

## 参数

| 项目 | 规则 | render.py 检查项（怎么量） |
|---|---|---|
| 画布 | 1024 × 1024，全出血，不画圆角（遮罩由系统加）；主体在 iOS 安全区（中心 824 × 824）以内 | 手查 |
| 线宽 | 60（`stroke-width` 写 60 ÷ k），只有一种；`stroke-linecap`、`stroke-linejoin` 都是 round | **线宽**：#body 的 stroke-width × k = 60 ± 1，所有线同一个宽度，圆头圆角，#body 里没有填色，#accent-shape 不描边，两层之外没有图形 |
| 线条段数 | 1–4 段相连的线 | **线条段数**：#body 渲染后的连通块数 |
| 强调色 | 正好 1 块 | **强调色块数** |
| 线间净空 | 分开的两段线之间 ≥ 60（一个线宽） | **线间净空**：每对线最近的边到边距离 |
| 夹缝 | 同一段线里不能有比线宽窄的缝：锐角拐角、贴得太近的两笔、太小的孔。拐角 ≥ 45°，孔的内径 ≥ 60 | **线间夹缝**：线稿用半径 30 的圆闭运算后，多出来的一块 > 3000 px² 就 FAIL（45° 拐角约 2200） |
| 强调色到线 | ≥ 60，不碰线 | **强调色到线**：40 净空的时候，small 版（线 76）在 40 px 下就粘上了 |
| 角 | 圆角矩形的角 r ≥ 56（线宽一半以上，内侧才看得出圆角）；多边形的角 ≥ 24（`shapes.py poly`），播放三角 24；强调色的角 ≥ 20 | 手查 |
| 关键线（起稿尺寸，量线的外沿） | `circle` 外径 600；`square` 540 × 540；`tall` 480 × 600；`wide` 600 × 480。`open`（缺口的框、组合）按凸包起稿：目标凸包约 290k px²（Tide 287k） | **形状**：外框比关键线大多少，只报 INFO |
| 长边 | ≤ 720，含凸起 | **长边** |
| 视觉大小 | 封闭的线稿（`circle` / `square` / `tall` / `wide`）：剪影面积是 Tide 的 0.90–1.10 倍。`open`：凸包面积是 Tide 凸包的 0.90–1.15 倍 | **剪影面积 / 凸包面积**：剪影 = 线 ∪ 强调色，半径 30 闭运算后填洞。Tide 基准从 `examples/tide.svg` 现场算（剪影 261 400、凸包 286 500）。不在范围时报告直接给出「k 改为 …」。**墨量**（INFO）：实际上色的面积和 Tide 比 |
| 重心 | 剪影质心离 (512, 512) ≤ 12。`open`：横向取剪影质心和外框中心的中点，纵向取质心。顶部有细凸起（最窄处 < 80）时，主体中心落在 (512, 530 ± 6) | **重心**，不过时报告直接给出「translate 改为 (…)」 |
| 强调色占比 | 强调色占剪影凸包的 6–20 %；AI 斜带 6–14 %。图片的太阳 r 78 约 6.5 % | **强调色占比** |
| 线渐变 | 竖直线性，跨度 600，中点在线的上下范围（含线宽）的中心 | **线渐变** 600 ± 8 |
| 强调色渐变 | 竖直线性，「浅 → 主」，跨度 480，中点在强调色上下范围的中心 | **强调色渐变** 480 ± 8 |
| 体积层 | 一个平涂实形，`#FFFFFF`、`fill-opacity` .14，不描边、不渐变、不带 `opacity`；画在 #body 之前；边沿走线的中线，藏在线（或强调色）下面；强调色可以压在上面，但离线照样 ≥ 60。开口的形状沿某一笔的中线封口 | **体积层**：边沿 ≥ 90 % 在线或强调色下，伸出凸包 ≤ 1 %；占凸包多少只报数。剪影、凸包、墨量都只按线 ∪ 强调色量，不算体积层 |
| 辉光和滤镜 | 不画。#subject 里出现 `filter`、#glow 就 FAIL | **辉光和滤镜** |
| 亮度对比 | 默认外观：线对底 ≥ 7:1（示例约 12:1），强调色对底 ≥ 3:1。线对体积层（约 7.7:1）、浅色外观只报 INFO | **线对底 / 强调色对底**：只取完全覆盖的像素 |
| 颜色 | 只用「颜色」一节的值 | **颜色**：底、线、强调色三个渐变各是规定的那一对值，不加第三个颜色、不半透明；体积层是 `#FFFFFF` .14；单个元素不带自己的 fill、stroke、stroke-width、opacity |
| 类别记号 | 见「类别记号」 | **类别记号** |
| 小尺寸 | 64 px 及以下用 small 版：线 76，体积层不变。favicon-16 只要剪影认得出 | **小尺寸**：small 版缩到 40 px，按亮度分出的形数和孔数和 1024 px 一样（FAIL 级）；29 px、16 px 只报 INFO（29 px 时强调色多半贴上线，是已知取舍） |
| 商店边缘、安卓主题图标、Android / PWA | 母版不用为它们改 | INFO，见「商店图标的 A/B 变体」和 `construction.md`「平台导出」 |

起稿顺序：直接按最终像素画（k = 1），线的中线坐标照关键线减去半个线宽；画完看剪影比或凸包比，不够时照报告改 k（stroke-width 跟着改成 60 ÷ k，`shapes.py --k` 重出圆角和强调色）；translate 照报告改。Tide 是尺寸基准：外框 560 × 694，剪影质心 (512, 509)。

## 颜色

**平面外观**（只画默认，其余由脚本生成；这四张是导出 PNG 和 Android 用的）：

| 元素 | 默认（石墨） | 浅色 | 深色（iOS Dark） | 单色 |
|---|---|---|---|---|
| 底 `#bg`（从上到下） | `#26282B → #191C1F` | `#FBFCFE → #E9EBEE` | `#191C1F → #0E1115` | 透明 |
| 线 `#body-fill`（从上到下） | `#F8F9FB → #C6C8CB` | `#333538 → #1E2022` | `#EDEEEF → #BDBFC2` | `#FFFFFF` |
| 强调色 `#accent` | 色板「浅 → 主」 | 同左 | 同左 | `#FFFFFF`，不透明度 .5 |
| 体积层 `#volume` | `#FFFFFF` .14 | `#1E2022` .07 | `#FFFFFF` .10 | `#FFFFFF` .30 |

底是 CIE LCh 色相 265、彩度 2.5 的冷石墨：默认 L 16 → 10，浅色 L 99 → 93，深色 L 10 → 5。线 L 98 → 80。只用竖直线性渐变，不用纯黑。

**iOS 26 的六种外观。** Apple 的外观是：默认、深色、Clear 浅色、Clear 深色、Tinted 浅色、Tinted 深色。Icon Composer 里层不变：默认和深色各设一套背景渐变和体积层透明度（深色 10 %），Clear 和 Tinted 由系统从单色派生（线白、强调色 50 %、体积层 30 %）。报告的「iOS 26」一排用近似的 Liquid Glass 把六种都画出来，只用来看结构在不在；真实效果以 Icon Composer 预览为准。

**iOS 深色外观交透明底。** asset catalog 的 Dark 用 `ios-1024-dark.png`（去掉底，线用深色外观的渐变，体积层 .10）；Icon Composer 里层不变，只在 Background 的 Dark 设渐变。

**Android 是派生的。** 自适应图标、主题图标、Play 512 都从同一个 SVG 导出，不另画；只按 Android 的规格调安全区和单色层。

**安卓主题图标。** 启动器用 Material You 色调给 monochrome 层重新上色：石墨底和强调色都没了，只剩线，强调色是同一个颜色的半透明。对照图模拟浅色、深色主题各一张；上架前还要在真机启动器上看一遍。

**强调色**（浅 → 主），每枚只选一个：

| 名 | 色值 | 适合 | 界面主色 |
|---|---|---|---|
| 蓝 | `#7AAEFF → #3B7BEA` | 工具类；四类以外的 app 没有品牌色、物件也没有颜色时的默认 | 蓝 |
| 绿 | `#6FD3A6 → #23A36B` | 只给健康、财务 | 绿 |
| 黄 | `#FFD978 → #F2AE2E` | 图片类 | 蓝 |
| 珊瑚 | `#FF9C86 → #EC5B45` | 视频类 | 蓝 |
| 紫 | `#B3A6FF → #7A63F0` | AI 类 | 紫 |
| 灰 | `#C8C7C3 → #8E8D89` | 单色图标、极简 | 蓝 |

选色顺序：先看类别。工具、图片、视频、AI 和健康、财务的颜色是定的，不看品牌色。不属于这些类的 app：品牌色（取表里最接近的，绿除外）→ 物件在现实里的颜色 → 蓝。不自造颜色。

「界面主色」是 `rian-app-theme` 生成 UI 主题时的主色：暖色和灰只留在图标和界面的品牌插图里（品牌位的面板深色模式是这枚图标的石墨、浅色模式是浅石墨，插图是平涂的 `<name>-mark` / `-mark-light` 线稿，原色不变），控件回落到蓝。

## 强调色

- **只有一处，一块填色**：可以是物件的一部分（进度扇形、太阳、抽出的切片、箭头），也可以就是第二个物件（剪辑手柄、扫描光束），或者 AI 斜带（`data-accent="band"`）。
- **不描边**，也不用强调色画线：强调色描的线和白线一样细，单色版里就是一条灰线，看不出哪一处是重点。
- **隔一个线宽**：离任何一条线都 ≥ 60，不贴边，不压线。
- **可以压在体积层上**：强调色是第 3 组，画在体积层之上；它和线的净空照旧 ≥ 60。
- **不加辉光。** 旧版强调色底下那层模糊副本去掉了，光由 Liquid Glass 加。
- **已知取舍**（只报 INFO，写进交付说明，不用改）：浅色外观里强调色对底多半不到 3:1；以「亮」为含义的线（Halo 的白云）在浅色外观里变成深色线；29 px 时强调色多半和线贴上，40 px 的 small 版还分得开。

## 类别记号

四类 app 各有一个固定的形状记号，和颜色一起由 `data-category` 决定。记号之外仍然画这个 app 自己的物件，记号不代替隐喻。

按 app 的主要功能归类，依次判断，命中就停：

1. **AI**：主要功能靠模型完成（问答、生成、AI 放大和修图）→ `ai`。只是带了一个 AI 功能的不算。
2. **图片**：处理的对象是照片和图片（编辑、压缩、抠图、相册）→ `image`。
3. **视频**：处理的对象是视频（剪辑、转 GIF、录屏、播放）→ `video`。
4. **工具**：处理文件和数据的工具（扫描、格式转换、文件管理、解压、计算器、扫码）→ `tools`。
5. **健康、财务**：运动、睡眠、记账、预算 → `health`、`finance`。
6. 都不是：计时、天气、笔记、阅读、翻译、输入法、词典这类不写 `data-category`。

| 类别 | `data-category` | 强调色 | 记号 | render.py 查什么 |
|---|---|---|---|---|
| 工具 | `tools` | 蓝 | 一条**水平直线**横贯整幅线稿 | 线 ∪ 强调色里有一行连续的墨 ≥ 外框宽度的 95 %，高 ≥ 30；中线在高度 35–75 %；只有这一条（两条读成菜单、等号） |
| 图片 | `image` | 黄 | 左上角一个完整的圆形太阳，就是强调色 | 面积 ÷ πR² ≥ 0.92；R ≥ 72；圆心在外框左上 42 % × 42 % 以内 |
| 视频 | `video` | 珊瑚 | 一个线画的播放三角，尖朝右，不和别的线相连 | 某段线围出一个尖朝右的三角孔，实测高 ≥ 110 |
| AI | `ai` | 紫 | 外轮廓右下角一道 45° 斜角，旁边一条「/」向斜带，宽 80，就是强调色，写 `data-accent="band"` | 方向 45°「/」± 1.5，宽 80 ± 3；占比 6–14 %；中心在外框右下；`data-shape="circle"` 上不能用 |
| 健康、财务 | `health`、`finance` | 绿 | 没有形状记号 | 只查颜色 |

- **工具**：横线可以是白线（Convert 下面那支箭头），也可以是强调色的胶囊（Scan 的扫描光束）；被它穿过的线在两侧各停在 60 以外。同一套里的两个工具 app 一个放上、一个放下。
- **图片**：太阳是一个整圆，不切，r ≥ 72，离线 ≥ 60，固定在左上角：放在照片框里面的左上，或者压在照片框的左上角上（框的线在太阳两侧各停在 60 以外）。单独飘着的圆点会读成状态点。
- **视频**：`shapes.py play CX CY H`，H ≥ 240 ÷ k（实测孔高约 H ÷ 1.7）。三角是线，不是强调色：强调色另找一块（剪辑手柄、循环箭头）。
- **AI**：外轮廓在右下角走一道 45° 斜角，`shapes.py aiband X1 Y1 X2 Y2`（斜角中线的两端，左下到右上）打印斜带：宽 80，离线 60。不放在圆形物件上：圆 + 斜带像 Linear 的标。
- **绿只给健康、财务，斜带只给 AI**：别的 app 用了，不写 `data-category` 也 FAIL。
- 不属于这些类的 app 不写 `data-category`，报告只给 INFO。强调色别放在左上（图片太阳的角）和右下（AI 斜带的角）。

## 商店图标的 A/B 变体

深色 App Store 里，默认外观的石墨底对黑只有约 1.3:1（报告的**商店边缘**一行），图标边缘看不见。母版不改，`render.py --store-ab` 另出变体给 App Store 的产品页优化（A/B 测试）用：

| 变体 | 根上的 `data-variant` | 改了什么 | 边缘对黑 |
|---|---|---|---|
| 浅一档 | `lighter` | 底 `#323538 → #26282B`（L 22 → 16） | 约 1.5:1 |
| 细亮边 | `rim` | 底不变；Apple 图标外形里最外 16 px 一圈亮边 `#66686C → #44474A`，`<path id="rim">` 放在 `#background` 和 `#subject` 之间 | 约 2.9:1 |
| 类别色（可选） | `tint` | 底朝强调色的色相偏一点，L 16 → 10，彩度 6：蓝 `#262730 → #1A1B23`、黄 `#2D2720 → #201B13`、珊瑚 `#302523 → #241917`、紫 `#29272F → #1D1A22`、绿 `#212A24 → #151E18`；灰没有 | 约 1.3:1 |

- 变体只换底或加边，线、强调色和位置都和母版一样。`data-variant` 只出现在 `--store-ab` 写出的文件上。
- 用法（也写在 `store-ab/README.txt`）：只在 App Store Connect 的产品页优化里和主图标对照，一次只比一项。测试图标要作为备用图标打进当前上架版本的安装包，并且和主图标一眼看出是同一个 app（审核规则 2.3.8）。细亮边只出平面 PNG，不进 Icon Composer，也不用在 Android 和网页上。变体文件不出 `--export`。
- 对比图 `<name>-store-ab.png`：默认和各变体放在黑、白两种商店底上，每格 120 px 和 60 px 两档。

## 系列检查

一套 app 在主屏和商店里并排出现，像的两枚会互相抵消。新图标定稿前，和已有的所有图标一起跑：

```bash
python3 scripts/series.py new.svg [more.svg ...] --with <已有图标>.svg ... -o renders
```

- `series-sheet.png`：所有图标 40 px 和 29 px 各一排（深底、浅底），离线最近的几对放大并排，加一张强调色位置图。
- **配对分数** 0–1 = 0.3 × 外形（闭运算、填洞后的剪影，各自缩到同一个框里比 IoU，再乘两者宽高比之比）+ 0.3 × 布局（small 版在自己外框的 12 × 12 格上，线落在哪）+ 0.4 × 强调色（40 px 下强调色位置的重叠 × 色相接近度）。≥ 0.37 标「像」。同一类别的两枚只比外形和布局，÷ 0.6，≥ 0.50 标「像」。
- 线稿的剪影多半是圆角矩形一类的大块，外形分偏高：标了「像」先改轮廓（长宽比、缺口、强调色压在框角上），不要只换强调色的位置。
- **强调色登记**：相距 < 160 的强调色连成一组，3 枚及以上标「扎堆」；两个图片、两个 AI 的不连。别的类别的强调色落在左上或右下，标「占了记号的角」。
- 没给 `--with` 时和 `examples/` 比，示例只作参考：配对照算，扎堆不算。新图标要做到 0 对像、0 处扎堆、0 处占了记号的角。
- 分数是粗筛，同一类别的两枚（两个视频 app 都有播放三角）分数不高也要用眼睛在 29 px 那排看一遍。

## 不要

- 不透明的实心主体、白色块（体积层只能是 .14 的半透明，边藏在线下）；体积层描边、渐变、伸出线外；第二种线宽、发丝线、粗细对比；方头、尖角拐角
- 字母、文字、数字；✦ 闪光、大脑、魔杖这类 AI 符号（AI 用右下角的斜带）
- 用强调色描线；第二个强调色；彩虹渐变，紫、青、粉的渐变球
- 底用径向光、光斑、噪点、纹理、暗角、边缘高光（`--store-ab` 的细亮边变体除外）、纯黑 `#000`
- 辉光、任何滤镜；投影、斜面、内阴影、镜面高光、折射、玻璃、金属、3D 透视；预先画好的圆角或圆形遮罩
- 比线宽窄的缝、锐角拐角、太小的孔；强调色压线或贴线
- 画成 Linear 的标；圆形物件上放 AI 斜带；照搬同名 SF Symbol / Material Symbol / Lucide 图标；沿用 examples 的整体框架
- 一枚图标里放两个隐喻；借用别的类别专用的东西：绿只给健康、财务，斜带只给 AI；四类以外的 app 也别在左上角放整圆太阳、别画单独的播放三角
