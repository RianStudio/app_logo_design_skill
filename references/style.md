# 风格规则：石墨

一句话：**深石墨底上放一块亮色实形，用 48 px 的负形切口分出结构，强调色只点一处。** 几何实形加等宽切口学 Linear 的标志；1024 全出血母版、分层和交给系统的玻璃质感学 Apple；单色主题图标、自适应图标和 Play 规格学 Google。

这份文件是所有数字的唯一出处。所有 px 都是缩放后的最终像素（1024 画布上），不是源坐标；源坐标 = 最终像素 ÷ k（k 是 `#subject` 的 scale）。角、切口方向和夹角、安全区要手查，其余数字 `scripts/render.py` 每次都逐条打印，标 PASS / FAIL / INFO，以它为准。

## 原则

1. **实形，不是线。** 主体由 2–4 块实心几何形组成（一般 3–4 块，第 5 块只给确实需要的），整个图标没有一条描边。
2. **切口分结构。** 相邻两块之间是一道 48 宽（量最窄处）的负形切口，露出底色。切口代替了线条：结构靠它看出来，变成单色以后结构还在。
3. **一眼看懂。** 一个隐喻，画一个具体的物件（秒表、云、饼图），3–4 块就能认出来，主屏上扫一眼就知道是什么 app。块越多，29 px 下越容易糊成一团。
4. **强调色只点一处。** 一整块实形，最好就是物件里最有意义的那一块（计时的进度、天气的太阳、记账抽出的那一块），和主体之间隔一道切口。
5. **几何。** 只用圆、圆角矩形、胶囊、扇形、环段、圆角多边形（含播放三角），以及它们的并集；每块都能报出尺寸。
6. **顶光，不画立体。** 底是石墨竖直渐变，主体是一束顶光照下来的亮灰渐变，强调色可以带一层极淡的辉光。投影、高光、折射交给系统（iOS 26 起的 Liquid Glass）；Android 和 PWA 用平面版，靠主体渐变就够了。
7. **类别看图形。** 工具、图片、视频、AI 四类各有一个固定的形状记号，见「类别记号」。类别配色只是内部的组织规则：只靠颜色，用户说不出类别（黄读成太阳、便签，珊瑚读成电量、录音）。

## 构成

```
#background      石墨底：1024 全出血 rect，fill url(#bg)
#subject         整体缩放和居中（transform），data-shape，data-cut="48"，data-category（属于四类或健康、财务时）
  #glow          可选：强调色块的模糊副本，第一个子元素
  #body          <g fill="url(#body-fill)">：主体的所有实形，共用一个渐变
  #accent-shape  一个元素：强调色实形，fill url(#accent)
```

只画默认（石墨）外观。浅色、深色、单色、小尺寸版由 `render.py --variants` 生成，配方在 `construction.md`「外观」。商店 A/B 测试用的浅一档底、细亮边、类别色底由 `render.py --store-ab` 生成，是额外导出，不是第二种风格，见「商店图标的 A/B 变体」。每个 id、class、data 属性的写法见 `construction.md`「属性和类」。

## 切口

| 项目 | 规则 |
|---|---|
| 宽度 | 最窄处统一 **48**（画布的 4.7 %，关键线圆直径的 8.3 %；Linear 原标是 7.4 %，这里放宽一点给 29 px 留余量）。64 px 及以下用 small 版，切口放宽到 64（40 px 时约 2.5 px，29 px 时约 1.8 px） |
| 宽窄 | 由几何算出来的切口全程 48：径向（`ring --gap 48`）、同心（半径差 48）、平移的扇形（外移 48 ÷ sin(θ ÷ 2)）、外扩 48 后减掉（`minus`）。**自由 45° 弦切口只在切点是 48，离开切点会变宽**（Halo 从 48 张到约 95，沿边 p50 71 / p90 85），这是已知取舍；平边对圆弧也会张开一点（Tide 冠钮对表圈 54 / 65）。render.py 的切口宽只量最窄处，宽窄看 `cut_spread`（INFO，平行切口约 48 / 52）和眼睛 |
| 相邻 | 两块最近距离 < 96 就算相邻，必须正好 48 ± 2。不想让它们相邻，就拉开到 ≥ 96 |
| 贯穿 | 每道切口两端都落在外轮廓外面，真正把形体切成两块；不留一头在形体里面的槽 |
| 方向 | 物件几何决定的切口照几何走：径向（环段接缝）、同心（表盘和表圈）、平行于边（饼图切片）。**强调色外扩 48 再从主体里减掉**形成的切口（气泡、书签、字幕条）跟着强调色的轮廓走，也算几何决定，不受 45° 限制，只要切口和主体轮廓的夹角 ≥ 45°。不由几何决定的**自由切口一律 45°**，「\」向（左上到右下）。例：Halo 的太阳和云之间是自由切口，用一条 45° 的弦把太阳切成弓形；不要反过来把主体（云）的轮廓外扩去切强调色，那是一条有机曲线。例外两处，都是类别记号：工具类那道贯穿的切口是**水平**的；AI 斜带和主体之间的切口是「/」向（左下到右上） |
| 夹角 | 切口切出来的角可以是尖的，但切线和轮廓的夹角 ≥ 45°，不切出细楔 |
| 不重叠 | 主体在强调色那块的位置真正挖空（直接写进路径、evenodd 或 mask），不能只靠强调色盖住，否则单色版会透出来 |
| 写法 | 优先直接写进路径：环段两端写成和接缝半径平行、往段内偏 24 的直线；被弦切开的圆写成弓形；抽出的扇形整块平移；盖在主体上的强调色用 `shapes.py minus` 从主体里减掉它外扩 48 的轮廓。`#cut` mask 只作起稿手段，交付前烘焙成路径，这样 Icon Composer 分层是纯路径。写法见 `construction.md`「几何速查」 |

## 参数

| 项目 | 规则 | render.py 检查项（怎么量） |
|---|---|---|
| 画布 | 1024 × 1024，全出血，不画圆角（遮罩由系统加）；主体在 iOS 安全区（中心 824 × 824）以内 | 手查 |
| 块数 | 2–4 块（一般 3–4），其中强调色正好 1 块。第 5 块只给确实需要的，在 `#subject` 上写 `data-pieces-why` 说明为什么。`class="detail"` 只给面积 < 2 % 凸包的碎块 | **块数**：去掉 `class="detail"` 后的连通块 2–4；5 块时没写 `data-pieces-why` 算 FAIL，6 块及以上都 FAIL。面积 < 2 % 凸包的碎块没标 detail 算 FAIL，≥ 2 % 的块标了 detail 也算 FAIL。另查强调色块数 = 1 |
| 切口 | 48，见「切口」；`data-cut="48"` | **切口宽**：所有相邻块对的最窄处 48 ± 2；强调色和主体分开渲染后直接量最近距离，也要 48 ± 2（贴边、粘成一块、离得更远都 FAIL）；`data-cut` 和实测一致；有 `#cuts` 时 stroke-width × k = 48 ± 1。**切口沿边宽**（INFO）：每对相邻块沿边相对的间距 p50 / p90。另查**切口贯穿**：单块自己闭运算（半径 30）后不能多出 > 1500 px² 的槽 |
| 实形最薄处 | ≥ 72（切口的 1.5 倍）；环形实形（进度环、表圈）≥ 84，small 版 erode 8 之后还剩 68 | **实形最薄处**：八边形开运算（半径 34）后每块保留 ≥ 80 % 面积，而且开运算去掉的部分离保留区最远 ≤ 68（45° 尖角约 55；细杆、夹角 < 45° 的细楔会超）。detail 块不查（小尺寸时删掉） |
| 角 | 圆角矩形 rx ≥ 短边的 20 %；扇形三个角圆角 24（`shapes.py sector`）；多边形的角圆角 ≥ 24（`shapes.py poly`），播放三角 32；凹角用 r ≥ 24 的反向圆弧；凹角对着另一块的圆角（半径 ρ）时，取 r = ρ + 48 且同心，拐角处切口才保持 48（Ledgerly：切片顶点 24，缺口凹角 72） | 手查 |
| 关键线（起稿尺寸） | `circle` 外径 580；`square` 520 × 520；`tall` 464 × 580；`wide` 580 × 464。`open` 不按关键线，按凸包起稿：目标凸包约 300k px²（Tide 299k）；对角错开的组合凸包约占外框的 70–75 %，所以外框面积约 400k（例如 690 × 580；Halo 704 × 558）。按「关键线 +10 %」起稿会偏小（盲测 600 × 530 只有 0.79×）。亮实形在深底上会显得比实际大（光渗），所以关键线收得比满幅产品图标小；只借 Google 产品图标「每种形状一条关键线」的方法，不用它的比例 | **关键线**：外框比关键线大多少，只报 INFO（起稿参考；大小由下面的剪影比 / 凸包比判） |
| 长边 | ≤ 720，含凸起 | **长边** |
| 视觉大小 | 实形（`circle` / `square` / `tall` / `wide`）：剪影面积是 Tide 的 0.90–1.10 倍。`open`（组合形状，比如云加太阳）：凸包面积是 Tide 凸包的 0.90–1.15 倍 | **剪影比 / 凸包比**：剪影 = `#body ∪ #accent-shape`，先用半径 30 的闭运算合上切口，再填洞。Tide 基准从 `examples/tide.svg` 现场算（剪影 278 700、凸包 298 700）。`open` 的剪影比只报 INFO（自由切口留下的楔形空隙合不上，Halo 只有 0.86）。不在范围时报告直接给出「k 改为 …」。**墨量**（INFO）：实际上色的面积和 Tide 比，并排时的轻重主要看它（三枚示例 1.00 / 1.11 / 1.17） |
| 重心 | 剪影质心离 (512, 512) ≤ 12。`open`：横向取剪影质心和外框中心的中点（对角错开的组合只按质心居中，会被推向轻的那一角），纵向仍取质心，离 (512, 512) ≤ 12。顶部有凸起时，改为主体本身的中心落在 (512, 530 ± 6) | **重心**，不过时报告直接给出「translate 改为 (…)」。凸起 = 半径 40 的开运算去得掉的部分，即最窄处 < 80。最窄处 ≥ 80 的冠钮（Tide 是 84）算进主体，仍按剪影质心判。Halo：质心 (518, 512)、外框中心 x 489，取中 (503, 512)，外框左右边距 137 / 183 |
| 强调色占比 | 可见强调色占剪影凸包的 10–25 %。一对同类物体（互换的两支箭头、一问一答两个气泡）里较小或一样大的那个当强调色时，写 `data-accent="pair"`，放宽到 10–33 %；AI 斜带（`data-accent="band"`）10–18 %。同一套尽量拉平（三枚示例 16.9 / 17.5 / 17.5 %） | **强调色占比**；`pair` 另查强调色面积 ≤ 最大一块主体的凸包（强调色得是较小的那个） |
| 不重叠 | 主体和强调色不叠 | **不重叠**：`#body` 和 `#accent-shape` 的像素交集 ≤ 强调色面积的 0.2 % |
| 主体渐变 | 竖直线性，跨度 600，中点在主体上下范围的中心；所有块共用一个 | **主体渐变跨度** 600 ± 8 |
| 强调色渐变 | 竖直线性，「浅 → 主」，跨度 480，中点在强调色块上下范围的中心 | **强调色渐变跨度** 480 ± 8 |
| 辉光 | 可选，最多 1 个，只给强调色：颜色取强调色的「主」，不透明度 ≤ .16，stdDeviation ≤ 28（三枚示例都用 24），不偏移 | **辉光**：从 `#glow-blur` 读 flood-opacity 和 stdDeviation × k |
| 切口清晰度 | 辉光渗进切口后，切口中线和底的明度差 ΔL ≤ 8 | **切口清晰度** |
| 亮度对比 | 默认外观：主体对底 ≥ 7:1（三枚示例 11.5–11.8:1），强调色对底 ≥ 3:1（六色都过；三枚示例珊瑚 6.2、黄 10.0、绿 6.5:1）。浅色外观只报 INFO | **亮度对比**：主体、强调色像素平均色对凸包内的底平均色，WCAG 对比度 |
| 描边 | 没有 | **无描边**：`#subject` 里（mask 之外）出现任何非 none 的 stroke 就 FAIL |
| 颜色 | 只用「颜色」一节的值；`#background` 就是一个 1024 的 rect，里面不放东西 | **色板**：`#bg`、`#body-fill` 等于默认外观的那一对值（`--store-ab` 写出的变体按根上的 `data-variant` 查它那一对底，细亮边另查 `#rim-fill`），`#accent` 是六色表里的一对；每个渐变的所有 stop 只能取那一对值（中间加第三个颜色、亮带都 FAIL），不半透明；`#body`、`#accent-shape` 里的单块不带自己的 fill，也不带 opacity / fill-opacity。**结构**另查 `#background` 是一个覆盖整张画布、没有子元素的 rect（底上的光斑、纹理会 FAIL） |
| 类别记号 | 见「类别记号」；`#subject` 写 `data-category` | **类别记号**：强调色是不是这一类的颜色，记号在不在、位置和尺寸对不对。绿只给健康、财务，斜带只给 AI，没写 `data-category` 也查；没写又不犯这两条的只报 INFO（不属于四类） |
| 小尺寸 | 64 px 及以下用 small 版：erode 8，切口 48 → 64，删掉 `class="detail"`，去掉辉光。面积 < 2 % 凸包的碎块标 `class="detail"`。favicon-16 只要剪影认得出，切口糊住不算问题 | **小尺寸**：small 版缩到 40 px，按亮度重新分块，块数和 1024 px 一样（FAIL 级）；29 px 和 16 px 只报 INFO。三枚示例在 40 和 29 px 都是 4 / 2 / 2 块，16 px 是 2 / 1 / 2 块 |
| 商店边缘 | 见「商店图标的 A/B 变体」 | **商店边缘**（INFO）：iOS 遮罩里最外 16 px 的平均色对黑（深色 App Store）和对白的对比度，附三种变体对黑的数字。母版的底是固定的，这几个数每枚都一样 |
| 安卓主题图标 | 母版不用为它改，见「颜色」 | **安卓主题图标**（INFO）：浅色、深色主题的 Material You 色调下，图形和强调色（alpha .5）对主题底的对比度。固定参考，每枚都一样；认不认得出看对照图的两格 |
| Android / PWA | 母版不用为它改 | **r_max** 和两个缩放系数，见 `construction.md`「平台导出」 |

起稿顺序：直接按最终像素画（k = 1），实形按关键线、`open` 按凸包定大小；画完看剪影比或凸包比，不够时照报告改 k，并用 `shapes.py --k` 重出带切口的路径；translate 照报告改。Tide 是尺寸基准：外框 580 × 712，剪影质心 (512, 512)。

## 颜色

**四种外观**（只画默认，其余由脚本生成）：

| 元素 | 默认（石墨） | 浅色 | 深色（iOS Dark） | 单色 |
|---|---|---|---|---|
| 底 `#bg`（从上到下） | `#26282B → #191C1F` | `#FBFCFE → #E9EBEE` | `#191C1F → #0E1115` | 透明 |
| 主体 `#body-fill`（从上到下） | `#F8F9FB → #C6C8CB` | `#333538 → #1E2022` | `#EDEEEF → #BDBFC2` | `#FFFFFF` |
| 强调色 `#accent` | 色板「浅 → 主」 | 同左 | 同左 | `#FFFFFF`，不透明度 .5 |
| 辉光 | 可选，≤ .16 | 去掉 | 保留 | 去掉 |

底是 CIE LCh 色相 265、彩度 2.5 的冷石墨：默认 L 16 → 10，浅色 L 99 → 93，深色 L 10 → 5。主体 L 98 → 80（ΔL 18：ΔL 12 在 180 px 下看不出顶光，实形发平）。只用竖直线性渐变，不用纯黑。

**iOS 深色外观交透明底。** Apple 建议深色图标不画底，由系统垫统一的深色底：asset catalog 的 Dark 用 `ios-1024-dark.png`（去掉底，主体用深色外观的渐变，保留辉光）；Icon Composer 里层不变，只在 Background 的 Dark 设渐变。上表深色那一列的底只用于对照图和 `<name>-dark.png`（`rian-app-theme` 预览用）。

**安卓主题图标。** Android 13 起开启主题图标后，启动器用 Material You 色调（色相取自壁纸）给 monochrome 层重新上色，浅色、深色系统主题各用一对：石墨底和强调色都没了，只剩形状，强调色是同一个颜色的半透明。对照图模拟浅色主题（放在浅壁纸上）和深色主题（放在深壁纸上）各一张（色调是近似值，见 `sources.md`）；上架前还要在开启主题图标的真机启动器上看一遍。

**强调色**（浅 → 主），每枚只选一个：

| 名 | 色值 | 适合 | 界面主色 |
|---|---|---|---|
| 蓝 | `#7AAEFF → #3B7BEA` | 工具类；四类以外的 app 没有品牌色、物件也没有颜色时的默认 | 蓝 |
| 绿 | `#6FD3A6 → #23A36B` | 只给健康、财务 | 绿 |
| 黄 | `#FFD978 → #F2AE2E` | 图片类 | 蓝 |
| 珊瑚 | `#FF9C86 → #EC5B45` | 视频类 | 蓝 |
| 紫 | `#B3A6FF → #7A63F0` | AI 类 | 紫 |
| 灰 | `#C8C7C3 → #8E8D89` | 单色图标、极简（强调色块显示为中灰） | 蓝 |

选色顺序：先看类别。工具、图片、视频、AI 和健康、财务的颜色是定的（render.py 按 `data-category` 查），不看品牌色。不属于这些类的 app（计时、天气、笔记）：品牌色（取表里最接近的，绿除外）→ 物件在现实里的颜色 → 蓝。不自造颜色。

「界面主色」是 `rian-app-theme` 生成 UI 主题时的主色：暖色和灰只留在图标里，界面回落到蓝。想让界面和图标同色，只能选蓝、绿、紫。按类别：工具（图标蓝、界面蓝）、图片（图标黄、界面蓝）、视频（图标珊瑚、界面蓝）、AI（图标紫、界面紫）、健康和财务（图标绿、界面绿）。

## 强调色

- **只有一处**：一整块实形，可以是物件的一部分（进度环段、太阳、抽出的切片），也可以就是第二个物件（书签、前面那个气泡），或者 AI 斜带（`data-accent="band"`）。
- **一对物体**：隐喻本身是一对同类物体时（互换的两支箭头、一问一答两个气泡），较小或一样大的那个当强调色，写 `data-accent="pair"`，占比上限 33 %，不用为了压到 25 % 硬画成一大一小。
- **永远隔一道 48 的切口**，不直接贴边，不互相压。
- **辉光**只给强调色，只有一层，放在 `#subject` 最底层。不透明度到 .24 再配上「浅 → 主」渐变就偏糖果感，图标会比界面吵，所以上限 .16。
- **已知取舍**（只报 INFO，写进交付说明，不用改）：
  - 浅色外观里强调色对底多半不到 3:1（三枚示例：黄 1.4、绿 2.2、珊瑚 2.3:1），靠深色主体撑住识别。
  - 以「亮」为含义的主体（Halo 的白云）在浅色外观里变成深色，会读成乌云。营销主图和商店截图用默认石墨版，不用浅色版。

## 类别记号

四类 app 各有一个固定的形状记号，和颜色一起由 `data-category` 决定。记号之外仍然画这个 app 自己的物件，记号不代替隐喻。

按 app 的主要功能归类，依次判断，命中就停：

1. **AI**：主要功能靠模型完成（问答、生成、AI 放大和修图）→ `ai`。只是带了一个 AI 功能的不算。
2. **图片**：处理的对象是照片和图片（编辑、压缩、抠图、相册）→ `image`。
3. **视频**：处理的对象是视频（剪辑、转 GIF、录屏、播放）→ `video`。
4. **工具**：处理文件和数据的工具（扫描、格式转换、文件管理、解压、计算器、扫码）→ `tools`。
5. **健康、财务**：运动、睡眠、记账、预算 → `health`、`finance`。
6. 都不是：计时、天气、笔记、阅读、翻译、输入法、词典这类不写 `data-category`。

render.py 的**类别记号**一行逐项查：

| 类别 | `data-category` | 强调色 | 记号 | render.py 查什么 |
|---|---|---|---|---|
| 工具 | `tools` | 蓝 | 一道**水平**切口（48）贯穿整个剪影，把图标分成上下两部分 | 有一段 48 ± 3 的空行把剪影上下分开，而且只有这一段（卡片中间夹一条色条是两段，FAIL）；中线在剪影高度的 35–75 %；上下两边对齐的水平直边 ≥ 宽度的 25 % |
| 图片 | `image` | 黄 | 左上角一个完整的圆形太阳，就是强调色 | 面积 ÷ πR² ≥ 0.92（不切、不缺）；R ≥ 100；圆心在外框左上 40 % × 40 % 以内 |
| 视频 | `video` | 珊瑚 | 一块实形里挖空的播放三角，尖朝右 | 某块实形里有尖朝右的三角孔，实测高 ≥ 150 |
| AI | `ai` | 紫 | 右下角一条「/」向 45° 斜带，宽 96，就是强调色，写 `data-accent="band"` | 带的方向 45°「/」± 1.5，宽 96 ± 3；占比 10–18 %；中心在外框右下（横、纵占比的平均 ≥ 65 %，各自 ≥ 50 %）；`data-shape="circle"` 上不能用 |
| 健康、财务 | `health`、`finance` | 绿 | 没有形状记号 | 只查颜色 |

- **工具**：把物件分成上下两块，中间隔一道水平的 48，切口两头都通到剪影外面。只有这一道：一张卡片中间横一条色条（上下各一道）读成汉堡菜单，不算。上下哪一块是强调色都行（一张页面立在蓝色底座上；上下两支半箭头）；同一套里的两个工具 app 一个放上、一个放下。
- **图片**：太阳是一个整圆，不被弦切（和 Halo 的弓形太阳不同），r ≥ 100（再小强调色就不到 10 %），和主体之间隔 48，固定在左上角。太阳最好落在一张照片的角上，单独飘着的圆点会读成状态点。
- **视频**：`shapes.py play CX CY H --r 32`，H ≥ 200 ÷ k（H 是源坐标；k = 1 时就是 200，实测约 152），再用 `minus` 从片子、屏幕这类主要实形里挖掉（结果是两圈，写 `fill-rule="evenodd"`）；三角四周剩下的实形仍然 ≥ 72。三角是镂空的，不是强调色：强调色另找一块（进度、剪辑手柄、循环箭头）。
- **AI**：`shapes.py aiband "<外轮廓>" --chamfer 48` 把外轮廓的右下角沿 45° 斜着切下，打印主体和斜带两条 path，斜带和主体之间隔 48。chamfer 是斜带外沿到外轮廓最右下点的距离；那个角的圆角是 R 时，chamfer ≥ 0.3 R，斜带两端才落在直边上。占比 10–18 %：不到 10 % 时 29 px 下只剩一条细线，加大 chamfer 让带往里移、变长。不放在圆形物件上：圆 + 斜带像 Linear 的标（render.py 判 FAIL）。
- **绿只给健康、财务，斜带只给 AI**：别的 app 用了，不写 `data-category` 也 FAIL。
- 不属于这些类的 app（计时、天气、笔记）不写 `data-category`，报告只给 INFO。强调色别放在左上（图片太阳的角）和右下（AI 斜带的角），系列检查会标「占了记号的角」。

## 商店图标的 A/B 变体

深色 App Store 里，默认外观的石墨底对黑只有约 1.3:1（报告的**商店边缘**一行），图标边缘看不见。母版不改，`render.py --store-ab` 另出变体给 App Store 的产品页优化（A/B 测试）用：

| 变体 | 根上的 `data-variant` | 改了什么 | 边缘对黑（三枚示例） |
|---|---|---|---|
| 浅一档 | `lighter` | 底 `#323538 → #26282B`（L 22 → 16：默认底的顶色变成它的底色） | 约 1.5:1 |
| 细亮边 | `rim` | 底不变；Apple 图标外形（圆角 22.37 %、60 % 平滑）里最外 16 px 一圈亮边 `#66686C → #44474A`（L 44 → 30，色相 265、彩度 2.5），`<path id="rim">` 放在 `#background` 和 `#subject` 之间 | 约 2.9:1 |
| 类别色（可选） | `tint` | 底朝强调色的色相偏一点，L 16 → 10，彩度 6（默认 2.5）；四类以外的 app 也按强调色的色相出，对比图上叫「强调色底」：蓝 `#262730 → #1A1B23`、黄 `#2D2720 → #201B13`、珊瑚 `#302523 → #241917`、紫 `#29272F → #1D1A22`、绿 `#212A24 → #151E18`；灰没有 | 约 1.3:1 |

- 变体只换底或加边，主体、强调色、切口和位置都和母版一样。`data-variant` 只出现在 `--store-ab` 写出的文件上，render.py 按它查那一对底；手画的母版底仍然只能是默认石墨。
- 类别色底让类别落在占图标大部分面积的底上，代价是系列感弱一点，也不提亮边缘，只作备选。
- 用法（也写在 `store-ab/README.txt`）：只在 App Store Connect 的产品页优化里和主图标对照，一次只比一项（默认对浅一档，或默认对细亮边）。测试图标要作为备用图标（alternate app icon）打进当前上架版本的安装包，并且和主图标一眼看出是同一个 app（审核规则 2.3.8）。深色和 Tinted 外观沿用母版的导出。细亮边只出平面 PNG，不进 Icon Composer（玻璃自带边缘高光），也不用在 Android 和网页上。亮边按 Apple 遮罩的近似画（对照图的 iOS 遮罩也是它），真实遮罩差一两个像素，上传前在 App Store Connect 的预览里看一眼四个角。变体文件不出 `--export`。
- 测出来的结果只决定这个 app 的商店图标，不改石墨母版的规则。
- 对比图 `<name>-store-ab.png`：默认和各变体放在黑、白两种商店底上，每格 120 px 和 60 px 两档，标出边缘对比度。

## 系列检查

一套 app 在主屏和商店里并排出现，像的两枚会互相抵消。新图标定稿前，和已有的所有图标一起跑：

```bash
python3 scripts/series.py new.svg [more.svg ...] --with <已有图标>.svg ... -o renders
```

- `series-sheet.png`：所有图标 40 px 和 29 px 各一排（深底、浅底），离线最近的几对放大并排，加一张强调色位置图。
- **配对分数** 0–1 = 0.3 × 外形（合上切口、填洞后的剪影，各自缩到同一个框里比 IoU，再乘两者宽高比之比）+ 0.3 × 布局（small 版在自己外框的 12 × 12 格上，块和切口落在哪）+ 0.4 × 强调色（40 px 下强调色位置的重叠 × 色相接近度 1 − Δh ÷ 60°）。≥ 0.37 标「像」。
- **同一类别的两枚**颜色和记号本来就一样，只比外形和布局：(0.3 × 外形 + 0.3 × 布局) ÷ 0.6，≥ 0.50 标「像」。比不同类别的严：强调色已经撞了，外形就要拉得更开。
- 标了「像」就改外形（轮廓、长宽比、块怎么分）或强调色的位置。强调色那项乘了色相接近度，换颜色也会降分，但用户不靠颜色认 app，只靠换色压到线下的不算过。
- **强调色登记**：每枚强调色的质心，和它在画布中心的哪个方向（8 个方向，离中心 80 以内算「中」）。相距 < 160 的强调色连成一组，3 枚及以上标「扎堆」；两个图片、两个 AI 的不连（太阳和斜带本来就在那个角）。别的类别的强调色落在左上（图片太阳）或右下（AI 斜带），标「占了记号的角」。
- 没给 `--with` 时和 `examples/` 比，示例只作参考：配对照算（别照搬示例的框架），扎堆不算。只涉及已有图标的配对和扎堆会列出来，单独标注，不算进汇总。新图标要做到 0 对像、0 处扎堆、0 处占了记号的角。
- 分数是粗筛，同一类别的两枚（比如两个视频 app 都有播放三角）分数不高也要用眼睛在 29 px 那排看一遍。

## 不要

- 字母、文字、数字；✦ 闪光、大脑、魔杖这类 AI 符号（AI 用右下角的斜带）
- 任何描边（mask 里画切口用的描边不算）
- 第二个强调色；彩虹渐变，紫、青、粉的渐变球（Linear 2019–22 年的旧标，已经过时）
- 底用径向光、光斑、噪点、纹理、暗角、边缘高光（`--store-ab` 的细亮边变体除外）、纯黑 `#000`；底铺满强调色；母版改底色（浅一档、类别色只出现在 `--store-ab` 的变体里）
- 投影、斜面、内阴影、镜面高光、折射、玻璃、金属、3D 透视；预先画好的圆角或圆形遮罩
- 小于 48 的切口；薄于 72 的实形（环形薄于 84）和伸出去的细杆；不贯穿的切口；夹角 < 45° 的细楔；主体和强调色重叠或贴边；把大块标成 detail
- 画成 Linear 的标（一个圆被 45° 切开，旁边几条平行带）；圆形物件上放 AI 斜带；照搬同名 SF Symbol / Material Symbol 的剪影；沿用 examples 的整体框架
- 一枚图标里放两个隐喻；借用别的类别专用的东西：绿只给健康、财务，斜带只给 AI（这两条 render.py 查）；四类以外的 app 也别在左上角放整圆太阳、别挖镂空播放三角，免得读成图片、视频类。黄、珊瑚、蓝、紫不是专用色，四类以外的 app 按品牌色或物件颜色照用
