# 套路登记表：一眼就是「生成的」图标

套路不是坏设计本身。它们大多起初是好主意，后来被默认地、到处地、没有理由地用，才变成一眼看穿的东西。所以这张表**写日期**，而且**不给替代品**：任何「换成这个」的清单，几个月后就是下一波套路。表里的「改」都是做法（从专属清单里找、按规则画），不是一个现成的形状或颜色。

做法参考 Taste-Skill（`references/sources.md`）的 tells 登记表，按 app 图标改写。状态一列说明谁来抓：**render.py** 是自动 FAIL；**打分** 是第 2 步概念打分会扣分；**评审** 是第 5 步看图评审时要找。

当前版本：2026-10。

## 1. 第一波（2023–2024）：通用 AI 图标

| 套路 | 谁抓 | 改 |
|---|---|---|
| 光滑 3D 团块、塑料高光、玻璃球 | render.py（`glow`、`palette`） | 线稿 + 体积层；光交给 Liquid Glass |
| 紫蓝渐变底、霓虹描边 | render.py（`palette` 查底和线） | 固定的石墨底；强调色一块填色，颜色随产品选（不限色） |
| AI 就画 ✦ 闪光、大脑、机器人头 | 打分（有自己的一处 = 0） | AI 类记号（右下角斜角加斜带）+ 这个产品自己的物件 |
| 想法画灯泡、增长画火箭、安全画盾牌加勾、待办画圆圈加勾 | 打分 | 换成这个产品产出的东西：它做完以后，用户手里多了什么 |
| 圆角方块里一个字母 | render.py 不抓，`SKILL.md` 第 2 步禁止 | 字母品类按第 2 步的品类表 |
| 翻译画地球、设置类工具画齿轮 | 打分 | 地球和齿轮是整个品类的，不是这一个 app 的 |
| 聊天气泡里三个点 | 打分 | 气泡里放这个 app 对话的结果（一行译文、一个答案） |

## 2. 第二波（2025）：「更高级」的装饰

| 套路 | 谁抓 | 改 |
|---|---|---|
| 烤进去的辉光、投影、折射 | render.py（`glow`） | 删掉：iOS 26 按层自己加 |
| 两三块强调色 | render.py（强调色块数） | 一块强调色（颜色不限） |
| 29 px 下就看不见的细节：刻度、小点、发丝线 | render.py（`small`、`line_gap`、`pinch`） | 删掉，或并进已有的一笔 |
| 物件斜放、悬浮、带地面投影 | 评审 | 正放、居中，按 Tide 的大小 |
| 网格背景、光斑背景 | render.py（`palette`） | 固定的石墨底 |

## 3. 第三波（2025–2026）：「修正」变成了新的样子

前两波的通用解法是「做成扁平线稿，克制一点」。模型把这个解法整个学走了，于是它本身成了最好认的生成样子，**也是本风格离得最近的坑**。

| 套路 | 谁抓 | 改 |
|---|---|---|
| 把 Lucide / SF Symbols 的同名符号原样放大，放在深色方块上 | 打分（有自己的一处）、评审（系统符号） | 先查同名符号，在轮廓或结构上改一处，而且这一处来自专属清单 |
| 「回避美学」：一个圆加一条线，或几块几何形，谁也说不出是什么 | 打分（像这个产品 = 0）、盲测 | 一个具体的物件。去掉套路以后空出来的地方要用这个产品自己的东西填，而不是留空 |
| 和同类前几名只差一个颜色 | 打分（竞品替换） | 换轮廓、换断口、换强调色是哪一块；只换颜色不算 |
| 强调色永远放在右上角一个小圆 | `series.py`（扎堆、占了记号的角） | 强调色是物件里最有意义的那一块，位置跟着意义走 |

## 4. 为什么只删掉还不够

一枚去掉了所有套路、却没有想法的图标，就是石墨底上的一个 Lucide 符号：规矩，但谁都能猜到它从「品类 + 禁止清单」里推出来。套路原本填的是**想法**该在的位置。所以流程先要想法（第 1 步的专属清单、第 2 步的竞品替换），再画，再检查；不要靠删套路来做设计。

## 维护

每次评审里发现一个新的重复出现的样子，就加一行：套路、谁抓、改（写做法，不写替代品），并改上面的版本日期。某一行被 render.py 自动抓住以后，把「谁抓」改成对应的 key。
